How well do the scans line up?

Real scans have no known right answer, so the registration is checked several independent ways. Errors are in millimeters, averaged over every point of the head.

Main result

64 mT T2 ← 3T T1, all 11 volunteers

How to read this: mutual information measures how well one scan's brightness predicts the other's. It should rise a lot from "before" (image centers lined up) to "after". The two error columns are two independent ways to check the answer when there's no known right answer; lower is better.

Consistency loop

A second route to the 3T T1, through the 3T T2

How to read this: the 64 mT scan is registered to the 3T T1 directly, and also to the 3T T2 from the same 3T session, which is then registered to the 3T T1. Both routes should send each point of the head to the same place; the loop error is how far apart they put it. This is stricter than self-consistency, which re-registers a moved copy of the same image. The last columns show how much the head moved between the 3T T1 and T2 sequences, which the loop measures instead of assuming it was zero.

A large loop error shows the two routes disagree, but not which one is wrong. sub-0064's routes both converge and both starting guesses agree; they just settle in different places. The 3T T2 has 3 mm slices and covers only 15 cm of the head, so it gives the registration less to hold on to. Both routes start from the same 64 mT scan, so a distortion in that scan would bend both the same way and stay hidden.

64 mT contrasts

T2, FLAIR and T1, each registered to the same 3T T1

How to read this: a bedside protocol has limited scan time, so it matters which 64 mT scan registers best. Every contrast is registered to the same 3T T1 with the same settings, so differences come from the 64 mT scan alone. The viewer's "64 mT scan" menu shows each one.

Repeat 64 mT sessions

Same volunteer, different days

How to read this: five volunteers had the 64 mT scan repeated on other days. Head position is how far the head sat from its first-session position in the scanner: scans from different days must be registered before they can be compared point by point. The loop error compares two routes to the 3T T1: through session 1, and directly from session N. The two 64 mT scans have independent noise and different head positions, so this loop catches problems tied to one particular scan.

Additional check: field strength or voxel size?

3T low-res scans as a control

How to read this: the 3T session also recorded each contrast at a low resolution close to the 64 mT one (1.38 × 1.38 × 5 mm vs 1.6 × 1.6 × 5 mm). Those 3T low-res scans go through exactly the same pipeline as the 64 mT scans. If their errors are about the same, the coarse voxels are what limits registration; if the 64 mT errors are clearly larger, the weaker signal and different contrast at 64 mT add to it.

The 3T low-res and high-res scans come from the same session, so they already share a coordinate frame. The registration doesn't use that: it starts from the same starting guesses as for 64 mT.
